## 1.0.1 大厅邀请回归

角色选择页的邀请按钮由 Online 直接添加到场景，不属于玩家 FocusEmulator 的焦点区域。1.0.0 的路由把它当成不属于本机玩家的按钮，从而拦截鼠标。

修复只精确放行前置的原生邀请按钮，保留原 pressed 回调和 Steam 邀请入口。不会放行远端物品面板，也不改变原按钮的禁用状态。

旧安装包复现：`20260919-013414-6131d6f3`，鼠标未发出原生 pressed，也未调用邀请入口。新包专项回归：`20260919-013455-1cc118e9`，房主 16 / 客户端 7 项通过，包含原生邀请、拖出释放取消、禁用按钮和防止背景角色误选。

测试加载实际前置和原生按钮，使用原 SessionManager 邀请回调，只将最外层 Steam 对象换为计数探针。断言 `activateGameOverlayInviteDialog` 收到正确大厅 ID 且每次点击只调用一次。**没有向任何好友发送邀请，也未验证 Steam 覆盖界面的实际显示**。继续存档场景原本没有该焦点拦截条件，本次保留其原生处理，未将其称为同一问题的复现。

测试 LAN 改用独立端口 29762，并停用测试进程的大厅发现，避免连接或干扰正常游戏的大厅。没有停止玩家正在运行的游戏。

## 测试方法与复现

隔离原游戏 PCK、独立游戏进程和测试存档，加载真实 Online ZIP 与构建的补丁 ZIP，通过前置的真实 LAN 会话连接 `127.0.0.1`。使用 `Input.parse_input_event` 注入鼠标移动、按下、释放、滚轮以及键盘输入，坐标使用当前视口变换；具体按钮操作沿用游戏及前置原信号。

测试设置确定的货币、奖励和解锁条件，以稳定复现操作。建房、加入及奖励搭建属于测试准备；不把直接调用菜单操作或同步入口算作鼠标通过。独立进程之间的测试文件只传递屏障和只读权威观察数据。

```powershell
python tools/build_mouse_ui.py
python tools/run_mouse_ui_tests.py --game-dir 'D:/Program Files (x86)/Steam/steamapps/common/Brotato' --case all --timeout 150
```

最新结果：`.local/mouse-ui-tests/20260919-013838-ebfb0583/summary.json`；1.0.0 记录：`.local/mouse-ui-tests/20260918-200150-742ed1cc/summary.json`，各组合下有每个进程的 JSON、日志和截图。测试使用独立 `BrotatoMouseUITests-*` 存档目录，没有读取或修改正常游戏存档。

## 验证边界

本次是单台 Windows 电脑上多个真实游戏进程的 LAN 验证。**尚未验证两台物理电脑或 Steam P2P**，也未覆盖全部角色、随机武器、道具组合、手柄型号和其他第三方 mod 的组合。

混合安装组合验证了选择和开局；奖励、商店等完整覆盖使用所有玩家均安装补丁的组合。建议房主和需要鼠标的客户端都安装。

兼容结论限于上述确切版本。游戏或 Online 更新后需重新检查扩展入口与同步行为。
